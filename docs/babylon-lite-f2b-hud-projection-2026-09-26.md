# F2b — native HUD projection, 2026-09-26

World nameplates, target health, and damage numbers now use Babylon Lite 1.31.1's public `projectWorldToScreenToRef` API with the camera view and view-projection matrices, active viewport, and canvas backing/CSS sizes. The adapter reuses its point, options, and result objects for labels and hides clipped/behind-camera marks. `observeCanvasLayout` also caches the canvas's screen offset so the fixed-position HUD follows its displayed surface. The source links the [Lite world-to-screen projection guide](https://github.com/BabylonJS/Babylon-Lite/blob/npm-lite-v1.31.1/docs/lite/architecture/54-world-screen-projection.md).

Focused canvas/projection tests pass (3/3) for front, behind, near, far, offscreen, active viewport, portrait/landscape, CSS/backing scale, device-pixel ratio, and result reuse. The game build and live camera check pass. I reviewed 1280×720 landscape and 390×844 portrait screenshots at device-pixel ratio 2; the live “Grave Shade” nameplate tracks its world target and disappears as the moving camera passes it. The reviewed [portrait motion clip](https://ve.sparkify.dev/wow-clone/ashen-reach/lite1311-f2b/2026-09-26-hud-portrait-motion.mp4) used a fixed actual 390×844 viewport and canvas, 230 timestamped frames, square pixels, rotation 0, and 2.735 seconds. VE returned seekable HTTP 206 `video/mp4`; Chromium played it at 390×844. The existing portrait health/hotbar overlap remains a separate responsive-HUD issue outside this projection change.
