# Progressive startup and performance takeover — 2026-09-27

Status: implementation and local verification in progress; production release results will be recorded below. This follows [the accepted investigation plan](one-second-startup-investigation-2026-09-26.md). The user accepts a playable starting neighborhood while the rest of the finite region loads.

## What was actually slowing the game

The screenshot reported 107 FPS at 1280×720. Two abandoned headless automation pages were still rendering against the same M1 Max GPU. The same walking measurement improved from **96.14 to 173.0 FPS** when those pages were frozen. A separate visible Chromium meadow measurement reached **197.60 FPS**. Production was still `fb1057d`, deployment `279d43aa-65e8-43ca-a454-e1bccff1d4c8`; Claude's startup commits had not reached production. These observations do not establish that Claude's commits caused the screenshot's slowdown.

A separate regression in the new progressive prototype was real: its interleaved 64-byte vertices cost approximately 18 FPS in shadow passes. Substituting position-only shadow geometry changed **148.95 to 167.80 FPS** with the same completed scene. The implementation now uses native 16-byte position storage for shadows, shares the index allocation, and keeps shadow meshes in a separate scene without a color render task. A later controlled comparison measured **166.79 FPS legacy / 165.30 FPS progressive**, with identical final triangle counts and seven enemies. Measurements are uncapped Chromium WebGPU at 1280×720 on M1 Max, without recording or competing game renderers.

Performance probes now create and close their own contexts. Disconnecting a CDP client alone leaves its page rendering. Existing unrelated interactive browser sessions were preserved; the two old automation pages were reversibly frozen.

## Implementation

- **P0: actual playable readiness.** The root serves the game directly. Havok and required downloads start early. Input unlocks only after dressed equipment, supported Havok grounding, and a completed rendered frame. `playableReady`, `combatReady`, `regionReady`, and the original full `ready` remain distinct. The probe checks real movement and GPU completion after an input event.
- **P1: prepared neighborhood.** The deterministic authoring generator supplies a compact gzip typed-buffer package for nearby world/collision, material definitions, sparse nearby foliage placements, and simplified existing skyline/tree geometry. No terrain or character geometry is silently replaced in the completed scene. Each generated manifest records source hashes, including generator dependencies and the package lock; a stale or corrupt prepared asset fails the build. Run `npm run prepare:startup` after authoring changes.
- **P2: dressed starter assets.** The body retains all **57 animations**, source vertices, skin weights, joints, and inverse bind matrices. The three initial clothing GLBs remain byte-identical after decompression. A 256-pixel body albedo is upgraded in place with native `rebuildMaterial`; the player, skeleton, heading, pose, and equipment sockets are retained. Tests compare the source and prepared accessors and animation samples.
- **P3: measured first playable area.** Native bundler grouping removes serial PBR/shadow module requests. Exact URL preloads and early thumbnail discovery overlap transfer and initialization. The full post/shadow pipeline remains active. Nearby vegetation is installed immediately after input unlocks, before the worker finishes the region; the first frame includes the dressed player, real starting ground, and skyline. The original 1.50 MB hypothesis was revised using measurements: the candidate observes approximately **3.58 MB** encoded traffic at the playable boundary.
- **P4: bounded remainder.** A module worker runs the same deterministic authoring generator and transfers geometry using an eight-credit queue. Render buffers have fixed ownership and range uploads. Collision chunks contain at most 512 triangles because native Havok cooking cannot yield within one shape. A visible railing with real Havok collision keeps the player inside safe terrain until all connecting collision is installed. There are no coordinate clamps or recovery teleports. A failed worker preserves installed chunks and player position; retry continues idempotently. Incompatible generator metadata requires a reload. Full foliage placements reuse the initial native instance pools. Enemy installation yields between bodies, and late collision waits for actual separation from the player.
- **P5: acceptance.** Cold-process, settled-frame, streaming-frame, traversal, disposal, failure, mobile and release checks are recorded separately below. A local compressed preview is not a production measurement or physical iPhone acceptance.

Default startup uses this path. `?legacyStart` retains the original full-world path for controlled comparisons. `VITE_FAST_START=0 ASHEN_LITE_BUNDLE=0 npm run build` produces the older packaging/startup behavior. `?preloadedEquipment` continues to select its compatible legacy body path.

## Evidence so far

A 20-run local compressed-preview series used fresh Chrome processes/profiles, initially empty HTTP caches, 1280×720, 50 Mbit/s download and 40 ms simulated latency. Playable times were **886.7–912.0 ms**, p95 **910.9 ms**. Input-to-observed movement plus a subsequent GPU completion was at most **51 ms**. Three unthrottled local runs measured **330.6–352.9 ms**; three 10 Mbit/s / 80 ms runs measured **3.288–3.306 s**. The slow-network result does not meet one second. OS, DNS, CDN and GPU-driver caches were not cleared.

A development streaming measurement recorded **264.50 FPS**, p95 **7.4 ms**, p99 **9.7 ms**, maximum **26.9 ms**, and two intervals over 16.67 ms. It is a separate workload from the settled seven-enemy performance gate. Individual background installations fell from **13.4 ms** at 4,096 collision triangles to approximately **1.9–2.4 ms** with smaller cooking batches. These are observed maxima, not hard real-time guarantees. Caller-owned world vertex/index storage is **210,049,236 bytes**; textures, Havok, other meshes, worker authoring memory and transient CPU arrays are additional.

The geometry equality experiment compared every completed position, index, UV, lamp UV and color against the original authoring output. A few nearly-zero normals differed between Node and browser math by less than 1e-14; this is numerical equivalence, not universal byte identity. The completed region retains its existing 128 m woodland LOD policy, routes, architecture and physical boundary.

## Review decisions

Two completed read-only Grok 4.6/high reviews and a bounded final delta inspection were used; the last inspection reached its turn limit without a final verdict. Valid findings led to explicit playable timing, bounded collision installation, source-mesh retirement, skyline/early foliage restoration, matching sky color space, failure/retry controls, idempotent collision installation after a failed GPU upload, and disposal on device loss. The live suite injects both worker failure and a failure after a successful collision cook.

The claim that stationary enemies never recheck spawn overlap was rejected: `tickEnemy()` calls `syncRoot()` every live tick, which calls `moveCollider()` even when the enemy has not moved. Light-shaft descriptors are retained; the current original scene has zero such shafts.

A full prepared-region download was rejected after an approximately 47 MB prototype; the worker preserves the existing much smaller transfer envelope. Consolidating all cooked collision back into six large shapes would reintroduce indivisible installation stalls. The measured settled comparison supports retaining smaller shapes. Fixed final index counts produce zero-area triangles for unfilled ranges during loading; Lite 1.31.1 has no applicable public mutable index-count API. This is a remaining loading cost, not the experimentally established cause of the completed-scene regression.

## Container comparison and scope decisions

An offline comparison exported the same 52 initial/proxy blocks through glTF Transform and standard `EXT_meshopt_compression`. The unquantized variant preserved every attribute value and triangle winding (the triangle codec rotates each triangle's indices cyclically). Its gzip payload was **829,344 bytes**, versus **975,927 bytes** for the current typed package. The filtered variant was **641,127 bytes**, with lossy filters; it was not selected as an appearance-preserving replacement. The unquantized Node decoding experiment took approximately 75–85 ms, which is not a browser upload benchmark.

The typed package retains direct CPU collision arrays, per-block offsets into preallocated native Lite storage, and shared position-only shadow storage. A glTF switch would need extraction and repacking into those same allocations or a different streaming mesh lifecycle. The current package meets the measured local time target, so this release accepts the 147 KB transfer difference and avoids adding an unverified runtime conversion. Standard Meshopt glTF remains in use for the source-compatible character. This is a deliberate bounded scope decision, not a claim that a custom container compresses better.

Nearby combat now initializes concurrently with distant geometry. It waits for nearby foliage so spell lighting captures the persistent foliage materials. Background character enhancement targets the original Human container even if the user switches race while loading. Native scene-disposal signals guard all asynchronous feature installers; immediate rejection observers prevent cancelled parallel jobs from becoming unhandled promises.

## Final candidate observations

The final Pages build (`ashenReach-gR-x8rgE.js`) reached playable in **886.7–912.0 ms**, p50 **901.3 ms**, p95 **910.9 ms** across 20 fresh-profile local compressed-preview runs at 50 Mbit/s / 40 ms. Completed encoded traffic at the boundary was **3,580,622 bytes**.

A separate uncapped background-loading run averaged **218.29 FPS**, p95 **9.6 ms**, p99 **11.4 ms**, maximum **35.7 ms**, with four intervals over 16.67 ms and no post-playable tasks over 50 ms. Its largest indivisible install was **3.3 ms**; the 1–2 ms slice is a scheduling target, not a guarantee for each native operation. Nearby combat was ready at 499 ms and all hostiles at 546 ms in that local unthrottled run. Full-region readiness was 9.34 seconds. A separate 60 Hz fresh-browser 50 Mbit/s / 40 ms waterfall reached full readiness at **17.55 seconds**, with **12.10 MB** total encoded traffic. This intentionally trades full-region latency for immediate local play and bounded frame work.

Reviewed live continuous-walk capture preserves the outfit and locomotion, shows the physical loading frontier opening, and continues to the town with Havok active and zero recovery teleports. Early silhouettes and grass refine visibly; high-resolution textures and distant foliage arrive later. The 1,178-frame MP4 retains 1280×720 square pixels and 19.079244 seconds versus 19.079842 captured elapsed seconds. Encoding now uses microsecond input timestamps and no B-frame reordering to avoid an observed 67 ms stream-duration undercount. Recording timings are not used as performance evidence.
