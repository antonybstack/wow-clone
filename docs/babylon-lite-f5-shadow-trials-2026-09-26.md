# F5 — Lite 1.31.1 shadow bridge trials (2026-09-26)

The public 1.31.1 shadow-enable API replaces the private CSM `_config._darkness` and `_forceRefreshEveryFrame` writes in `setEnabled()`. The application keeps its own `state.enabled` gate because its custom terrain, fog and post receivers need to bypass any depth map retained during a disabled pass. The CSM layout guard no longer checks `_config`. A live 1280×720 Chromium WebGPU check found 41 actor-shadow silhouette samples, 15.41 m keyboard movement, 38 PBR receivers, a shadowed street, a clear street while disabled, a shadowed street again after re-enable, portrait resizing and zero runtime or GPU errors. Six focused lifecycle tests pass.

Native caster membership did **not** replace the guarded task-retirement bridge. With that bridge removed, the first live actor-shadow check found zero affected samples; the same check with the bridge restored found 39. The source and test changes for that attempt were reverted. This is a direct behavioral regression in our moving skeletal caster path, so the version-gated retirement bridge remains until Lite offers equivalent behavior. The custom far PCF map and caster alias also retain their M2 ownership guards. See the [Lite CSM architecture](https://github.com/BabylonJS/Babylon-Lite/blob/npm-lite-v1.31.1/docs/lite/architecture/17-cascaded-shadow.md) and [M2 private bridge report](babylon-lite-m2-private-bridges-2026-09-26.md).

A reviewed [live 1280×720 motion clip](https://ve.sparkify.dev/wow-clone/ashen-reach/lite1311-f5/2026-09-26-shadow-motion.mp4) shows moving actor and tree shadows in the churchyard, then the lit town street. Its 1,424 timestamped frames span 15.841 seconds with zero runtime or GPU errors; the encoded MP4 is 15.842 seconds with square pixels. The recording helper now preserves sub-8 ms frame intervals instead of stretching them.

VE served the MP4 with byte-range playback; Telegram message **777** returned matching 1280×720 dimensions and 15.842-second duration.
