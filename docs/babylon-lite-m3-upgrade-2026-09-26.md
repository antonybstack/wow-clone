# M3 — Babylon Lite 1.31.1 compatibility migration

The package and lockfile pin `@babylonjs/lite` to exactly **1.31.1**; Havok remains **1.3.14**. All first-party uses of the four removed math exports now use `invertMat4`, `multiplyMat4`, `decomposeMat4`, and `createTranslationMat4`. Multiplication order and nullable inverse checks are unchanged. The local-light test fixture uses the renamed inverse, and its installed PBR template assertion follows the 1.31.1 mutable `roughness` and `surfaceAlbedo` declarations. See the [math API change](https://github.com/BabylonJS/Babylon-Lite/pull/688) and [1.31.1 release](https://github.com/BabylonJS/Babylon-Lite/releases/tag/npm-lite-v1.31.1).

The camera controller, CSM/PCF settings, render targets, PBR plugins, and probes remain as they were for a direct comparison. Installed Lite's `rebuildMaterial` now returns `void | Promise<void>` and internally catches/reports asynchronous rebuild errors; the current attach paths use normal scene registration/renderable build, and live HDR/local-light checks showed no omitted materials. M2's exact-version private-layout guards accept 1.31.1 and passed on the real target runtime.

A browser-only compatibility problem surfaced in `character-lab.html`: `/characters/base.glb` now carries meshopt-compressed data in two buffers, while the legacy fixture composer deliberately accepts a single embedded buffer. The lab now normalizes that fetched source once through glTF Transform WebIO and MeshoptDecoder before creating its two independent actors. The existing offline helper reuses the same browser-safe function. `ALL_EXTENSIONS` preserves the source's material metadata; the new fixture test compares material JSON, rig, animation count, and raw passthrough. The runtime game asset is unchanged. The [glTF Transform meshopt documentation](https://gltf-transform.dev/modules/extensions/classes/EXTMeshoptCompression) is linked at the helper.

Two live-check failures were stale test timing/data assumptions. `check-camera.mjs` no longer sends Escape after pointer-up, which could open the game menu before testing right orbit; it waits for pointer unlock and the application's 350 ms relock throttle. `check-two-handed.mjs` observes the short stow on animation frames starting before Fire Blast release, then checks spell damage as deltas from the dummy's current 2,000 HP rather than old 600-HP totals. The corrected camera check and all **18** two-handed assertions pass live on 1.31.1, with no input or gameplay behavior changed for these checks.

A separate clean worktree materialized public asset links, ran `npm ci` from the candidate lockfile, resolved exactly 1.31.1/1.3.14, and produced the same game bundle.
