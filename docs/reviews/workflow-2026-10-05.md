## What is working

| Practice | Evidence and why to keep it |
| --- | --- |
| Reuse native source/engine tools | The back fix changes indices through the existing glTF partitioner; it preserves vertices, morphs, skin and source clips instead of inventing another deformation system. Native GPU picking identifies the actual faces. |
| Independent preservation and failure checks | Written-file triangle union/bind/curve comparisons, failed/cancelled swaps and deliberate negative controls catch real corruption and vacuous tests. Keep these guards. |
| Matched live controls | Hair/glove/body visibility at the actual sprint pose identifies the back defect. Static walk was the wrong motion; a colour-based guess would have fixed the wrong thing. |
| Separate performance from recording | The capture HUD is not a benchmark. Tracked renderer ownership and quiet-machine runs protect the numbers; retain outliers and contaminated runs explicitly. |
| Narrow adversarial review | Grok's valid front-coverage objection reduced a 99-triangle central slab to 32 back-only triangles. A focused review at a meaningful decision boundary improves quality. |
| Immutable publishing and rollback | Source pins, content-addressed outputs, independent build/HTTP seals and the existing Pages workflow make a release reviewable and reversible. |

## What is not working

1. **Local completion is outrunning production delivery.** Nine product/source
   checkpoints after the M7 release improve identity, startup and controls, but
   M5 is still unreleased. Some were necessary; the current bottleneck is closing
   the release, not accumulating another broad checkpoint.
2. **Verification scope expands too easily.** The new matrix creates 3,150
   sampled views after the preceding 630-view sweep. Automated native-state
   checks are useful, but the parent visually inspected a subset. More captures
   do not automatically prove more visual acceptance. Tiny seams need matched
   close views and continuous motion before a large matrix.
3. **The working documentation repeats history.** Before this review, CURRENT
   is 330 lines, next-ten 441 and the M5 implementation plan 238: 1,009 lines
   before opening their result reports. Old and current limitations coexist,
   including historical WoW/goal-status statements. Re-reading this on every
   resume wastes context and makes stale facts look current.
4. **Tool output is too broad.** Full Telegram chat accessibility trees, large
   raw reports, minified matches and unbounded diffs consume context without
   answering the next decision. Read the target controls or summary; retain
   raw evidence in files. Do not print private unrelated chat content.
5. **Preparation and live-check sequencing are occasionally careless.** A
   mobile helper was started while the saved helper was still running. The
   ownership assertion correctly refused it before a second renderer opened,
   but the failed attempt was avoidable. A yielded process is still running;
   wait for exit and inactive ownership before the next helper.
6. **Media controls create avoidable overhead and measurement risk.** Closing
   Telegram's viewer can restart inline autoplay. Native/full-window UI states
   are easy to confuse, and repeated control attempts consume time. Finish one
   bounded playback check, leave it paused, and audit all media before FPS.
7. **Automation status has been described too confidently.** The native goal
   currently reports `blocked`; ongoing user-authorized work is possible, but
   an active automatic continuation guarantee cannot be inferred. Hooks are
   reminders and cannot keep a disconnected or ended runtime alive.

This review does not attribute every elapsed minute to these causes. Asset
correction and genuine runtime regressions still require investigation. The
execution has nevertheless overemphasized checkpoint volume and repeated
reporting relative to shipped player value.

## Changes to use immediately

- **One immediate plan.** CURRENT gives the production/local distinction,
  active package, next action, open gates and process ownership. The 12-hour
  plan owns current order; next-ten remains the broader queue; result reports
  own historical evidence. Archive the previous full CURRENT with its links
  preserved. Do not copy the same long checkpoint into three working files.
- **Choose evidence before running it.** For each package write the concrete
  problem, smallest discriminating check and exit. First reproduce in one
  native actor at a close matched pose; then inspect relevant adjacent fits;
  expand only when a new shared contract, failure or uncertainty warrants it.
- **Run tests according to change.** Preserve required release checks. During
  iteration run focused tests and the affected native live cases. Run the
  complete relevant suites once after source freeze. Repeat only after a new
  change/failure; a documentation-only change does not justify a fresh FPS grid.
- **Freeze before expensive gates.** Fix related source defects together,
  verify independently, freeze assets, then perform the prescribed final
  build/startup/FPS/release gates. Any later product change invalidates the
  affected gate; cosmetic report editing does not.
- **Bound performance investigations.** A failed comparison gets attribution
  and one prescribed paired confirmation. Preserve failed rows. Do not keep
  rerunning until a lucky pass or silently relax the gate. Recording and asset
  generation stay outside measurements.
- **Use one meaningful motion delivery per accepted visual package.** Inspect
  movement before recording. Capture the final relevant behavior, review it,
  deliver the MP4 with verified proportions and then associate the ledger with
  the finished commit. Do not make a new clip for every unchanged test run.
- **Output summaries, keep raw artifacts.** Cap search/diff outputs, use
  structured result summaries and inspect specific fields. Full logs, receipts
  and captures remain on disk; commit compact provenance and reviewed evidence.
  Verify the git tree includes intended bounded captures: project image ignore
  rules can silently exclude them from a directory-level add.
  Do not reload complete prior tool transcripts after a context reset.
- **Close a package and immediately choose the next.** Commit/push completed
  work promptly. Deployment gates are necessary; another permission round is
  not. At hours 2/5/9/12 report actual output and time remaining. At hour 5 a
  failed creator release takes priority over starting new content.
- **Use review selectively.** Use the user-selected reviewer for a bounded adversarial check of a
  concrete candidate/risk after useful implementation exists. Claude Opus 5.5 /
  high is now authorized for useful parallel work. Assign exact files; the worker
  owns no live rendering unless explicitly assigned. Parent verification
  remains responsible for tests and actual visual acceptance.

## How we judge the improvement

Measure production features and corrected visible defects, not number of tests,
screenshots, commits or documentation pages. At the end of this window record:

- Creator release ID, saved named-character behavior and any remaining failed gate.
- Final/public startup p95 and counts of misses; per-route FPS/tails and conditions.
- The real new item and reproducible factory output, if reached.
- Time spent implementing, debugging, verifying, publishing and documenting, when
  directly recorded. Do not invent a historical time allocation from commit dates.
- Repeated checks with their reason, and any avoidable ownership or stale-state retry.

The first result must be a stronger playable product on the production URL. The
factory is the next multiplier for quarterly armor work; broad Elf/crowd/world
work remains outside this focused window.

- The historical height helper used diagnostic shape query parameters that request source assets excluded from Pages. Use saved canonical appearance recipes for ordinary-release tests. Fix and assert the helper's failure list; a printed failure without a failing exit status is insufficient.
- The user now authorizes useful parallel work in the existing Claude session at Opus 5.5 / high. Bound review by file/task ownership, keep the parent responsible for source integration, live rendering and release, and verify the worker actually started instead of assuming an accepted terminal prompt proves execution.

- Run representative elevated routes in **both directions before performance gates**. The bridge and four contact fixtures passed, but a thin tower landing failed after the expensive 120-load/45-FPS grid. Preserve those receipts as the earlier build's evidence and refresh affected gates after repair. This was avoidable verification ordering, not additional delivered progress.
- An upward ray-hit normal does not prove a closed mesh's visible top was hit. A native query from inside the landing returned its underside with normal Y +1. Test inside/near-surface cases and reuse Lite's ignored-body shape cast from above the feet. Do not assume backface normals always point outward.
- Use an HTML video review wrapper when the browser's raw-media document prevents controls under request interception. Close owned media before benchmarks. Repeating failed raw-document controls or loading entire process command lines/logs wastes context without improving acceptance.

- Calibrate render counting against native animation-frame callbacks **before** the full FPS matrix. A standard-Chrome positive control unexpectedly submitted 227 FPS without pacing-removal flags. A three-second native diagnostic counted 180 RAF callbacks but 731 submissions: the four-slot scheduler permanently rendered from completion promises after saturation. Existing unit tests explicitly required that immediate wake behavior, so green tests protected the defect. Completion must enqueue one RAF, and tests must independently forbid rendering from acknowledgements. Prior submission-throughput rows and possible-240 flags remain recorded; they are not final frame-pacing acceptance.

- Keep a statistical pacing hint separate from independent cadence evidence. After the scheduler repair, a 235.85 FPS forest row still triggered the unchanged possible-240 band, but six same-context runs exceeded the hard ceiling by 76–100 frames. Retain every row and flag; validate launch controls, native callback admission and the deliberately capped control, then require a falsifying row in each affected cohort. Repeating a whole matrix until a hint vanishes would waste time and select favorable data. The first strict collector failure remains in the receipt.

- Check canvas dimensions in the capture manifest before treating a video as native-resolution evidence. The final first capture had a 1280×720 viewport but the automatic 0.75 render scale yielded a 960×540 canvas; it was retained as a diagnostic, and final motion was recaptured with explicit `pixelRatio=1`. The separate FPS measurements already forced a native 1280×720 canvas. A correctly sized MP4 alone does not establish internal game resolution.

- Check the public critical chain before treating local timing as release acceptance. Original clip compaction removes 403 KB but yields only 35 ms locally; the bottleneck moves to world readiness. Earlier optional discovery moves request starts without improving the transfer-bound hood body. Preserve this attribution and public failures; do not label a packaging change a one-second success from its theoretical byte saving.
- Closing Telegram's viewer can restart inline loops **after** an immediate pause audit. The first follow-up hood cohort was contaminated and retained as invalid. A temporary play-event pause guard plus before/after media checks keeps the isolated measurement quiet; remove the guard and restore only previously playing user references after all gates.
- Share pure runtime constants with build tooling instead of regex-parsing JavaScript. Keep save migration/validation in its existing owner. Presence-only discovery may fetch a small unused index; functional guards should prohibit wrong bodies/identity, rather than an obsolete blanket no-index assertion.
- Stop negative compression experiments when the retained bytes show no useful gain. Accessor deduplication, zero-tolerance resampling and lossless world Meshopt did not reduce this payload materially; none is shipped. Source-manifest provenance changes can invalidate native remote preparation even when piece bytes stay identical. Account for that dependency before freezing.
- Keep a world-specific verifier outside shared character compiler provenance. A validation-only world change should not force regeneration of unrelated character and remote assets. The skyline packet verifier now has its own owner and is called by world preparation and the release build.
- Review incremental work at its lifecycle boundaries before the timing grid. Holding worker/skyline requests exposed install, retirement, retry and disposal independently. Closing the owned tab and opening the wrapper directly recovered immediately. Native/full-window and Telegram verification should share one bounded cycle after timing, rather than repeatedly reopening media between cohorts.

Preserve existing call contracts, add the independent regression, and inspect background completion before accepting a faster startup.
