## Intended result

Deliver **The Bell of Vaelmark**, a complete exploration episode in the current
Gothic region: find the undercroft inscription, ascend the west bell tower, ring
the bell, return to an opened memorial reliquary, claim a journal relic, and bring
the discovery to Hollowmere. Navigation, lighting and reactions should make the
journey understandable from ordinary play. A first visit of roughly 15–25 minutes
is a design target to measure, not a reason to slow movement or add waiting.

The required core is the cathedral episode, Hollowmere return, persistent journal,
readable route and verified delivery. Eastwatch and additional regional discoveries are ordered
extensions. They are cut before core quality or the six-hour finishing reserve.
The [long-term vision](vision.md) explains the later combat, character and shared
world direction. Mobile remains backlogged.

## G10 A persistent memorial discovery

**Player outcome:** walk to the undercroft memorial, press X or the nearby button,
read its inscription, and find it again after reload in Menu → Journal.

1. Add a pure state contract with stable IDs and a monotonic episode sequence:
   `unstarted → inscription-read → bell-rung → relic-claimed → returned`.
   Readable content is data; logic validates allowed transitions. Re-reading
   content is harmless. Later milestones enable later transitions. Discovery
   records for other destinations are independent of episode phase.
2. Use a bounded record such as
   `{version:1, episode:"vaelmark-bell-v1", phase, discovered:[id...]}` under
   `ashen.exploration.v1`. It is one durable v1 journal per browser origin until
   an explicit later migration,
   shared across appearance changes, and explicitly local rather than a
   per-character/server entitlement. Reject oversized/unknown/invalid records;
   validate known IDs and phase prerequisites. No position or collider state is
   trusted from storage. Preserve invalid/unknown bytes before replacement, as
   the appearance store does; if backup/write fails, continue in memory with a
   visible session-only warning. Write only on successful state transitions.
3. Derive the first anchor from the existing undercroft metadata. Add named
   `memorial.standingSurfaceY`, `memorial.stand` and `memorial.interact` metadata;
   they do not exist yet. Derive a reachable standing point on the west long
   side from the authored memorial dimensions, and put the interaction point
   roughly 0.4 m outside its actual collider at readable chest height. Measure
   horizontal reach against that accessible point, not the tomb center or the
   overhead lamp. The lamp is 3.5 m above the floor and is unsuitable as a
   standing datum. Verify the final points in ordinary play. Do not scatter
   coordinates across UI, test and runtime files. Resolve content only after
   navigation is ready.
4. Add one nearby interaction owner. Select candidates from a small region-local
   list at at most 5 Hz using accumulated gameplay `dt`, then revalidate at
   activation. Initial bounds: horizontal distance ≤2.5 m and feet height within
   1.2 m of the authored standing surface. Derive feet from
   `player.body.position.y - player.capsuleHeight / 2`, as the cathedral guide
   does, so supported body height changes do not invalidate the test. Require
   active Havok and navigation readiness; a null query from unavailable physics
   is not evidence of a clear path. Use a self-filtered Havok line check
   from the character toward an accessible interaction point to reject walls.
   The point must sit in reachable air in front of the prop, not inside its
   collider. Check exact ray result semantics in `player.js`; do not treat every
   non-null hit as the intended prop. Reject triggers through ceilings/floors.
5. Add an edge-triggered `interactPressed` field at the existing `src/input.js`
   keyboard/HUD boundary. Use X after checking the live input map; currently it
   is unused. Avoid an independent document key listener. Ignore repeats,
   modifier shortcuts, form controls, menu/armory input, death, disposal and
   pending navigation. Both key and visible button call the same validated
   action. Use `isInputEnabled()` and `onInputReset()` for the existing visibility,
   modal and device-loss boundary; unsubscribe on disposal. Clear pending
   activation on blur, menu opening and death. Mount the button in an existing
   HUD widget container, or extend its widget filter narrowly, so clicking it
   cannot also enter mouselook or select a combat target. Preserve movement,
   targeting, spells and current pointer-lock behavior.
6. Add Menu → Journal through a late provider, following the region-map pattern.
   Show discovered text and the next concrete direction: “The west bell tower
   opens from the front terrace.” Link to the existing cathedral guide. Use
   existing menu focus/pause/Escape behavior and restore focus on close. Present
   the nearby prompt without hiding the player or combat HUD. Give that prompt
   its own DOM/status owner so its polling cannot overwrite spell refusal,
   damage or watchman messages in the existing combat HUD.
7. Construct the exploration owner inside `createCombat`, beside the existing
   region-map owner. Update it through `beforeAnimation`/`afterAnimation`; clear
   pending input and disable actions before returning for player death. Release
   listeners, UI, props and pending continuations with `sceneLifetime(scene)`
   and native scene disposal. Combat has no separate disposal owner to invent.
   In the early menu, expose only `getJournal:()=>combat?.journal`, following
   the existing late region-map provider and refresh pattern. Prevent new
   journal/content imports from entering `main.js` or `registerLateFeatures`
   on the initial boot graph.
   Add `?dev` → Developer tools → Exploration status/reset-session controls for
   reproducibility. Test state overrides stay session-only and labelled; they
   never silently overwrite the player's saved journal. No console-only helper.

**Checks:** pure transition/idempotence/validation and storage-failure tests;
ordinary near/read/reload; no activation from the nave above the memorial or through its wall;
death/menu/armory/focus gates; blocked storage still playable; abort removes
listeners/DOM and prevents late writes. Play from the undercroft entry with

  and west bell landing, with exact route/state and raw intervals retained. Record
