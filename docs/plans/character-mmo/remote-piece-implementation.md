# Native remote piece integration — milestone 6

Continue after five-design catalogue integration. This is an execution plan, not a capability claim. Public presence remains disabled without the verified host. Use only current accepted Human/Orc/Undead; M5 identity is a separate fit contract.

1. Prepare immutable **body and individual pieces**, never a Cartesian product of outfits. Human uses its existing full shape family. Re-encode Orc/Undead embedded textures with the current native glTF Transform/Sharp pipeline: preserve geometry/skin/morph/57 curves, retain the normal-map policy, independently reparse written bytes and compare each accessor, cyclic-winding indices, joint rest/inverse binds and source curves. Record source hashes, texture policy and exact written texture dimensions. Review both races in native motion before publishing the descriptor.
   Prepare animated bounds with Lite's existing `computeMaxExtents` and actual body source groups before mounting/mirroring. Garments borrow the verified race palette during this offline native pass. Include terminal rows and the native morph envelope; independently spot-check deformed vertices at source/action extremes. Store bounds per individual piece/hash and clips per body, never per outfit permutation. Runtime staging requires these source-hash-bound bounds; do not introduce per-frame geometry scans or bind-pose culling. Weapon bounds/positions continue to follow the evaluated native sockets.
2. Reuse `createStreamedEquipment`, `createEquipmentLoader`, native body visual/mixer and `attachSockets` for the first **eight exact** remote actors. There is no new locomotion, skinning, weapon socket or glTF decoder. Give each actor a native root and palette; pieces borrow only that palette and restore original skeleton ownership before disposal. Keep recipe/revision and source motion clock separate from the renderer owner. No remote Havok player controller.
3. Admit through the existing 32-ID latest-request queue, one preparation at a time, eight committed actors, at most one staging actor. Keep the existing immutable download ceiling at 8 MiB. Hold verified byte leases only while an actual decode/upload consumer needs them; decoded GPU owners have a separately accounted lifetime. Protect borrowed palettes through shader-build completion. Configure remote garment idle retention explicitly (zero initially), rather than multiplying the player's two-idle-piece cache by every remote actor. Reject unsupported budgets, fits, hashes and asset paths before native allocation.
4. A same-race equipment transaction uses the existing per-piece loader. Stage body/shape/race changes hidden; publish the complete new representation only after all required pieces and native material builds succeed. Failed, late or superseded requests leave the prior actor visible. Preserve live network transforms and source phase during staging. Keep native color/shadow membership correct when pieces and cores hide/show.
   Add only the lifecycle hooks that this actual consumer requires: bounded idle retention, a verified byte lease spanning native decode, and an awaited material-ready boundary before the existing synchronous visibility commit. Test cancellation during that boundary and drain preparation before retiring the actor palette. Do not make the player's ordinary path wait on a hook it does not use. The existing scene lifetime/retirement fence remains responsible for submitted GPU work; native decode/material compilation still need their own outstanding-owner lifetime.
5. Derive semantic masks from the published coverage and layer adapters. Match actual source clips with the existing actor sampling contract. Reuse the native manager and hand-grip/carry composition where the equipped pose requires them; document any finger override or quantization relative to raw source controls. Validate mesh-local socket transforms across mirror, height and distinct race binds. Native animated swept bounds must cover body, rigid plates and attachments; no bind-pose-only culling.
6. Gate catalogue compatibility through current discovery and seat validation before any remote state. Expand the presence validator only after its renderer supports the corresponding race/items. Normal local race changes and requested shape application must converge transactionally on accepted authority state. New unsupported fits remain rejected until actual proof; no fallback to Human geometry.
7. Run one actor first, then two real clients and eight seats. Include three races, Human endpoints, shoulder/new-design/mixed swaps, stale revisions, corrupt/failed/late pieces, shared consumers, cancellation and disposal. Independently inspect native poses, sleeves/waist/headwear, weapon sockets, shadows and bounds. Record live MP4, review and deliver VE/Telegram. Test 10 repeated complete lifecycle cycles plus bounded churn, with explicit resource counters and no final owners/leases.
8. Run isolated solo and separate eight-actor throughput, cold default and supported largest/new-design profiles, cathedral and mobile/WebKit checks. No thousand- or hundred-player capacity claim here. M8 adds projected-size/spatial tiers using native VAT/thin-instance APIs on **per-piece prototypes**, with matching race/bind/motion keys, after this exact composition boundary is accepted. Retain all startup and forest-pacing outliers.
