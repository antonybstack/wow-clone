# M006 licensed long-hair source audition

Status: **candidate proved in live motion; M006 entry gate remains open** (2026-09-28). Source base `595438c`. The default game and Pages assets are unchanged. This is a source-art experiment, not a creator control or an accepted hairstyle.

The [MakeHuman system-asset pack](https://static.makehumancommunity.org/assets/assetpacks/makehuman_system_assets.html) contains `long01` and `ponytail01`. The downloaded 280,737,770-byte `makehuman_system_assets_cc0.zip` matched SHA256 `b542127a8e25547c7c29c19f2d1d2adb9a664c80396ecd694095dbc8028a0107`. Both `.mhclo` and `.mhmat` file headers explicitly say CC0 released September 2020, unlike the conflicting AGPL header on the previously staged `mhair02`. [Pinned member hashes](../../../../blender/characters/candidates/hair/m006-provenance.json) are verified by the existing `fetch-makehuman.py --verify-only` path. These raw audition sources, including their large PNG textures, remain ignored and are fetched by that script from their pinned archive members. The build uses the existing MakeHuman proxy parser and Blender studio helpers, fits the authored UV mesh to the current Human head, and exports a masked material and the original 65-joint armature. The proxy and [glTF skin](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#skins) boundaries are cited in the build scripts.

The tail-only cut keeps faces whose centroid lies behind the measured scalp (`+Y > 12 cm` in the body's centimetre-local mesh frame). That threshold is an audition, not a portable tailoring rule. The mesh is parented and weighted Head → Neck → Spine2. The exported skin has all 65 named joints; the worst relative inverse-bind difference from the shipped body is **0.000775**, below the **0.002** Blender round-trip limit used for the M005 plate. Its material retains `MASK` alpha, the authored texture and UV, and double-sided rendering. The [candidate assembler](../../../../scripts/character-assets/assemble-long-hair-candidate.mjs) uses glTF Transform's `copyToDocument` to preserve those properties, remaps joint indices by name, attaches the hair to the body's skin, and confirms all **57** source clips remain. The combined diagnostic GLB is **7,431,280 bytes**, compared with the shipped body's **3,399,784 bytes**. That extra 4.03 MB is material for selected-style load time; it is absent from the default play payload and needs compression or a separate lazy fetch before release.

I reviewed the candidate in the actual Ashen Reach scene at 1280×720 through a full orbit, walk, run, jump and land: [10.082-second motion clip](https://ve.sparkify.dev/wow-clone/ashen-reach/character-mmo/m006-ponytail-audition-2026-09-28.mp4), Telegram **796**. An owned slot 7 (Vite **5873**, Chrome PID **94328**, CDP **10037**) intercepted exactly one body request and served the diagnostic GLB; its game page reported no errors. The clip has 200 ordered source frames with stable 1280×720 dimensions, square pixels and no rotation. Telegram returned matching 1280×720 metadata; VE served `video/mp4`, the exact 21,194,828-byte file, a 206 byte range, and advancing native 1280×720 playback in Chromium. Native Telegram inline/fullscreen was unavailable for independent inspection. Slot 7 was stopped afterward; user-owned CDP 9337 remained on `about:blank`. Recording was active, so this check makes **no FPS claim**.

The dark tint is a fixed audition value. Close views still need the tie/back boundary, head turns, helmet/hood concealment, cape contact, and slender/stout plus height extremes. A creator dye control must drive the fused base hair and the additive tail from one palette. The current candidate's large separate texture and 4,042 triangles are also unsuitable for a high-count crowd tier without a cheaper representation.

`fetch-makehuman.py --verify-only`, both Blender source exports, the assembled GLB round trip, Python/Node syntax checks, **87/87** character tests, **68/68** equipment tests and the Pages-mode build passed. The main built game chunk kept the M007 checkpoint hash (`ashenReach-Cp655D5h.js`), confirming this audition added no default-game import. The live check was a visual and animation check only; no isolated frame-rate or cold-load measurement was run for the diagnostic candidate.

The bald blocker remains. A diagnostic UV-region recolor found most of the sculpted crown but missed locks on the front-right and selected some nape faces; the three-angle offline inspection shows that a texture-island threshold is not a clean hair/scalp seam. It does not create a hidden scalp. The shipped head still needs a proper hairless scalp and a separate hair layer or a separately authored head variant, with face/neck continuity and the M004/M005 vertex contract checked. Adult age transfer is still untried. No creator, persistence, recipe capability, M007 fit acceptance, M008 race work, M009 crowd integration, M010 acceptance, or production deployment follows from this audition.

Reproduce the candidate with `python3 scripts/character-assets/fetch-makehuman.py --verify-only`, then `ASHEN_HAIR_STYLE=ponytail01 ASHEN_TAIL_ONLY=1 /Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python scripts/character-assets/build-long-hair-candidate.py`, followed by `node scripts/character-assets/assemble-long-hair-candidate.mjs ponytail01-tail`. The live recorder requires an owned harness slot and intercepts only its body request. Generated binaries and raw frames live under ignored `.cache/` and `ve-capture/`; the provenance, build/assembly/recording recipes and reviewed video URL are retained here.
