# M002 result — versioned appearance recipe

Status: **implemented, tested and live state checked** (2026-09-27). Source base: `bad1087` (M001). This milestone adds a pure data boundary and a separately invoked developer probe. It does not change game rendering, assets, persistence, or the default play import graph. No deployment was made.

## Contract and measured data

[`contract.js`](../../../../src/character/appearance/contract.js) fixes schema 1, `appearance-catalog-v1`, and the current Human/Orc/Undead fit families. The seven equipment slots are complete with explicit `null` empties. It reuses the equipment catalogue, declared per-race fits and occupancy validator. The `shape`, `components` and `dyes` objects are empty by design: no shipped slider, hair or dye asset supports a value yet. Elf is unsupported. Recipes are copied into a canonical field order and deeply frozen. Unknown fields, prototypes, accessors, wrong fit versions, unsupported items, occupancy conflicts, bad JSON and inputs above 16 KiB UTF-8 fail with typed field paths. The adapter takes an explicit `{race, loadout}` from committed `getState()` and has no game or resource-fetching dependency.

[`codec.js`](../../../../src/character/appearance/codec.js) emits exact canonical JSON. Its `appearanceKey` is that semantic content prefixed by `appearance:`; asset, material and detail revisions belong in any derived GPU-resource key. A catalog change needs an explicit version decision and migration fixtures, rather than silently rewriting v1. The fixed v1 profile values are tested against the current equipment contract.

The [four seeded recipes](../../../../scripts/fixtures/appearance/v1-recipes.json) derive from M001's active catalogue and presets. The fixture records the SHA-256 of both source catalogue/contract files and the deterministic generation expression; the test verifies those hashes. It contains project-authored identity data, with no third-party asset bytes. Encoded sizes are **294–374 bytes**: Human empty 294, Human Wayfarer 337, Undead Revenant 335 and Orc Warden 374. The fixture file SHA-256 is `161aac320798840bd08dad174c05c425e65173d007be1f15ccf215054eae9c7c`.

## Inputs and limits for later milestones

The current **active Undead garments still have the physical rest/inverse-bind mismatch** documented in [M001](m001.md); a logically valid Undead recipe does not prove shared-pose compatibility.
