# Ashen Reach combat overhaul

Date: 2026-10-10. Status: **investigation and proposed implementation plan; combat changes have not started**. Source inspected: a7df082. Latest user direction: fluid, satisfying World of Warcraft-inspired combat; global cooldown, instant casts, procs, damage over time, area attacks and buffs. Preserve the Gothic expedition. Desktop first; physical mobile defects remain backlogged.

## Outcome and scope

Build one excellent, original fire-caster kit in the existing region. A player should feel a button register immediately, move naturally between attacks, recognize a proc without studying a log, anticipate an enemy hit, and understand why damage happened. A 90-second fight should offer choices about movement, target, burn refresh, proc spending, area damage and interruption without forcing repetitive mana starvation.

First deliver the feel improvement with the existing three spells. Then add the smallest coherent set of mechanics and an encounter that makes them useful. Do not build several classes, a talent tree, equipment-stat overhaul, a generic ability scripting language, a new animation engine or an MMO combat server during this cycle. Keep a clean future authority boundary without describing local damage as multiplayer-ready. No WoW assets or proprietary animation extraction.

**Priority:** input and timing → movement and contact → readable information → interacting mechanics → an encounter → scalable polish. VFX begins in parallel after event semantics are agreed, but cannot mask failed timing or collision rules.

## Research and what we take from it

1. [Blizzard combat philosophy](https://news.blizzard.com/en-us/article/24246290/combat-philosophy-and-addon-disarmament-in-midnight): combat skill includes decisions under cast/cooldown constraints. Blizzard describes clearer telegraphs and native feedback to reduce dependence on external tools. For Ashen: readable choices with a small kit and built-in cues; avoid a mandatory rotation assistant.
2. [Blizzard cooldown manager plans](https://news.blizzard.com/en-us/article/24226697/the-cooldown-manager-and-future-updates): target debuffs, active buffs, remaining durations and selected sound notifications are useful first-class information. This is a design reference, not a claim that every announced option shipped unchanged.
3. [Legion Mage preview](https://worldofwarcraft.blizzard.com/en-gb/news/19941177): historical Fire design separates proc control from burn spreading and removes one proc-control action from the GCD. Search-indexed official text was accessible; direct article access returned 403. Use the general interaction lesson, not historical values as current retail rules.
4. [Shadowlands update notes](https://news.blizzard.com/en-us/article/23529209/shadowlands-content-update-notes) document deliberate off-GCD exceptions. For Ashen, interrupts and survival tools should respond during an offensive GCD; ordinary damage remains paced. This does not justify making every button off-GCD.
5. [Lite 1.31.1 animation architecture](https://github.com/BabylonJS/Babylon-Lite/blob/npm-lite-v1.31.1/docs/lite/architecture/07-animation.md) and installed `node_modules/@babylonjs/lite/index.d.ts`: reuse native groups, masks, weights, speed ratio and supported crossfades. The installed package is the authority for callable APIs. Add short reference-link comments at changed native API boundaries; link project timing policies to this plan so later agents understand their purpose.
6. [Lite feature comparison](https://github.com/BabylonJS/Babylon-Lite/blob/master/docs/lite/02-feature-comparison.md) distinguishes Lite from Classic, including missing Classic particle-system equivalents. Reuse our bounded mesh/billboard effects and native instance APIs; do not import Classic `ParticleSystem`, GUI or GlowLayer assuming parity. Master documentation can advance beyond our installed version.

**All values below are proposed Ashen tuning, not asserted WoW defaults.** We are borrowing interaction principles, not copying a particular expansion's rotation. Official sources do not establish an exact universal WoW queue window; 300 ms below is our starting setting.

## Timing and action contract

- Offensive GCD starts on successful action start: initially 1,500 ms. Haste later uses `max(1000, 1500 / (1 + haste))`; cast duration uses the same haste snapshot without that GCD floor. Keep ability cooldowns, recharge, periodic interval and projectile speed unchanged by haste initially. Starting values are adjustable through normal settings where appropriate and the Developer combat panel for diagnostics.
- One replaceable offensive queue slot, default 300 ms, configurable 100–400 ms plus Off. Queue only when the next legal start is within the window. The last admissible intentional press wins; outside-window input cannot erase a valid queued action. Queuing acknowledges intent but neither spends resources nor begins cooldown. Revalidate at execution; failure clears the slot once and explains why.
- Store action sequence, ability ID, target ID plus spawn generation, input time, earliest start and expiry. Target is selected at press time. Never silently redirect a queued spell to a new selection or a respawned actor. A later intentional press replaces it with the new target. Deadline is readiness plus one simulation update, capped at 100 ms lateness; do not resurrect an old queued action after a hitch or pause.
- Repeated presses of the current spell never cancel a cast. Escape first stops the current cast and queue, then follows existing target/menu behavior on a subsequent press. While pointer-locked, that first Escape also releases the lock and must still deliver Stop Casting before the existing early return/200 ms unlock guard. When a menu already owns focus, it handles Escape and no gameplay action is emitted. Explicit Stop Casting is bindable. Menu, journal/armory input takeover, death, blur and scene disposal clear queued input and prevent stuck keys.
- Instant means gameplay release on the accepting simulation update. Visual acknowledgement and initial hand flash begin within one presented frame under healthy frame pacing; damage resolves then for a direct spell or later for a projectile. Animation recovery never delays the next legal spell. No global hit-stop or freeze of Havok/rendering.
- Stationary Lava Ball can turn its upper body, but deliberate player translation or jump interrupts before release. Instants work while running, strafing and airborne. Ground-origin Pyre Burst requires actual grounded state when executing. Never apply a blanket movement multiplier.
- Validate target alive/hostile, generation, range, facing policy, resource and LOS at start and release. Target selection changing alone is not an interruption. Initially retain existing forgiving idle auto-facing; while steering, don't snap the camera or override movement. The exact facing cone is recorded in C01 and tested at its boundary. Idle auto-facing requires no translation, turn input or RMB look; otherwise a targeted direct spell uses a 90-degree half-angle facing gate and a clear refusal. Keep movement and camera orientation untouched by a refused cast.
- Instant cost and cooldown commit atomically on acceptance. Hard casts reserve mana at start; commit once at release; interruption releases reservation, retains the already elapsed GCD and does not start the spell cooldown. Queued abilities reserve nothing. HUD shows available versus reserved resource. Launched projectiles remain paid for if they miss, are blocked, or lose their target. No refund on cosmetic failure.
- Proc/charge consumption occurs exactly once at accepted execution, never at queue time. A proc expiring before execution causes normal revalidation; do not silently convert a queued instant-only request into a stationary cast. Store whether the press explicitly requires an instant variant. A normally queued Lava may upgrade if Surge becomes available before execution; an instant-only queued Lava must never downgrade into a stationary cast. Validate and consume the chosen variant atomically at execution.
- Off-GCD interrupt and ward bypass only the offensive GCD. They still obey their own resource/cooldown/state checks. They can execute during an offensive cast without cancelling it or overwriting its queued follow-up. Their VFX cannot steal the cast animation owner. While Lava owns the upper body, acknowledge Ward/Quench with HUD, sound and attached effects only; do not replace `input.castSpell` or call `cancelCast` for a second gesture.
- One combat clock is driven from the existing loop; no per-effect intervals or extra requestAnimationFrame loop. Advance from active elapsed time, excluding explicit solo pause/hidden time. Process deadlines in timestamp/sequence order: explicit death/interrupt, existing periodic ticks, player releases, melee contacts, generated projectile/direct impacts, then aura expiry; ties within a class use action sequence. Resolve each damage event fully, marking a lethal target and emitting its one kill event before the next event. C05 routes every damage source through that single reducer; existing enemy XP detection must consume the kill once, never also award it independently. Test 30/60/144 Hz and 120 ms active stalls. For an active gap over 500 ms, enter a visible solo pause using the existing menu/pause owner and clear pending input rather than delivering a burst of catch-up hits. Resume through the existing visible Resume action with a fresh time origin; test this separately from normal 120 ms hitch handling. Apply this only after play readiness, not during boot. Existing streaming stalls make this a required UX test in C02, not an excuse to mark startup fixed. This is a local-session policy; a future authoritative server continues simulation during client pause. Combat uses the full active elapsed interval up to 500 ms and drains due events in order; keep the existing Havok movement clamp unchanged. A queue readiness time 10 ms after the prior frame is 110 ms late after a 120 ms hitch and must expire without spending; readiness 50 ms after that frame is 70 ms late and executes once. No retroactive attacks from a dropped queue. Existing casts/ticks still resolve due deadlines once. Presentation samples/seeks its supported native animation phase from action elapsed time after a hitch so it does not accumulate the old 50 ms clamp drift. Projectile sweep uses the current collision world; do not fabricate historical target positions or add physics catch-up loops.
- Cosmetic quality and loaded assets never determine damage. Events carry `eventId`, `actionId`, `sourceId`, `targetId/generation`, simulation time, ability/variant, hit location, amount, damage type and flags. Missing sound/texture degrades presentation gracefully. Prevent duplicate kill/XP awards across simultaneous direct/periodic hits.

Numbers are a cohesive starting experiment, not accepted balance. Initial baseline remains unchanged through C02; tuning is introduced explicitly from C03/C05 onward.

**Ember Surge:** three Embers grant one banked proc, duration 10 s, maximum one banked proc. Eligible Fire Blast and ordinary Lava Ball direct hits build Embers; proc Lava Ball, Brand ticks, area secondary hits and triggered damage do not. While banked, eligible hits can retain at most two Embers toward the next proc; overflow is visible in developer statistics and does not recursively generate another proc. Crit chance starts at 15%, multiplier 1.5, from an injectable seeded random source for tests. Ordinary play uses a fresh seed. This bounded progress reduces long unlucky stretches without guaranteeing a crit; keep an event trace of real rolls.

**Example:** Brand → ordinary Lava Ball → Fire Blast while repositioning → Surge lights up → instant Lava Ball → refresh Brand late → Pyre Burst when three enemies cluster. Quench interrupts an enemy cast during a GCD; Ward buys time when movement is unsafe. These are choices, not an enforced rotation. A proc's value must survive a movement mechanic.

**Mana:** start 100, regenerate 6/s in combat and retain a separately tuned out-of-combat rate. Free filler and free proc spender guarantee an action at zero mana. A sustained 90 s priority sequence must not force more than 5% idle time solely from resource exhaustion; reckless area/ward spam may remain expensive. Rebalance current 360-HP shades and player survivability using actual fights, not dummy damage alone.

**Periodic rules:** aura key is `(source ID, target generation, effect ID)`. Reapplication from the same caster refreshes; different casters are independent for the future boundary. Snapshot damage multiplier on application/refresh; ticks do not crit or proc in the first implementation. Preserve `nextTickAt`; expiry extends by `base + min(remaining, 0.3 * base)`. Only complete scheduled ticks at or before expiry deal damage; no fractional expiry tick in this initial rule. Document this intentional choice. For this local release, caster death/release-spirit clears its outgoing burns and its buffs; target death, despawn, leash reset and disposal clear target effects. Increment enemy generation on respawn. Dummy recovery clears its outstanding auras/flights and increments a combat-reset generation even if its render object remains the same; an old hit must not enter the next test round. Existing launched effects must not attach to a new actor that reuses an ID. No offline damage or saved combat buffs on reload.

**Projectile policy:** retain the fixed-aim Lava trajectory during C02–03 baseline migration. C06 deliberately changes the tab-targeted nuke to follow its locked living target, with a swept Havok query for every movement segment; walls can still stop it. A target death/despawn cancels its damage without refund. Lifetime is capped at 4 s, travel at 60 m; never acquire another target. Use eight local gameplay flight slots initially, justified against the fastest supported cast rate and lifetime; if exhausted, refuse before commit with a recorded reason. Cosmetic pool exhaustion must never remove a gameplay flight. Test two simultaneous procs, a strafing target, a wall entering the path, and a reused actor ID. Record this gameplay change explicitly rather than treating it as cosmetic polish.

**Area rules:** broadphase nearby candidate list, then alive/hostile/generation, radius, vertical interval and actual Havok LOS. Initial vertical allowance 2.5 m relative to feet, validated on cathedral stairs and between floors. Pick nearest then stable ID up to five targets, not array insertion order. No terrain-ray sampling for every spark. Decorative visibility/frustum culling never controls gameplay hit eligibility. Ground-targeted persistent fields and automatic Brand spreading are deferred until the self-centered burst is readable and reliable.

**Enemy engagement:** damage from a valid local source must alert a living enemy even outside its 12 m proximity radius. Reuse its existing chase/cast/return owner. Tune pursuit distance with the proposed 30 m attack range and the actual navigable encounter bounds; do not globally remove the churchyard/town constraints. If the source cannot be pursued or attacked within that enemy's valid space, enter a visible Evading/return state, reject further damage while evading, clear hostile auras and reset at home without awarding XP. Add a bounded stuck-progress test so ranged attacks cannot farm a permanently trapped enemy. Direct damage and Brand ticks refresh combat while valid; leash reset ends those effects. C08 tests a long-range pull, a wall, a doorway, kiting to the leash edge and re-engagement. Preserve a viable mortal way to clear the Hollowmere route; change the old doorway test path if its success depended on an enemy being unable to retaliate. No general navmesh or threat-table rewrite is required for this solo slice.

### C03 — Remove unnecessary locks and align contact

1. Fire Blast direct damage releases at successful acceptance. Replace its long anticipation with a quick supported gesture; retain full authored clip for diagnostics if useful. Do not compress a full-body 1.4 s action indiscriminately and produce sliding feet.
2. Add a narrow presentation adapter that selects existing upper/lower clips and adjusts native group weights/speed. Keep locomotion in charge of moving legs. Later proc Lava can use a short release segment without its charge portion. Unsupported rigs use a safe abbreviated cosmetic fallback; lack of a clip cannot block a spell.
3. Make recovery interruptible by the next accepted spell; blend previous pose over a short 80–120 ms trial range. Tune actual gesture contact during live review. Upper-body animation must not reset Havok velocity, force camera turns or interrupt jumping for an instant.
4. Split movement/grounding validation by ability rather than leaving the shared grounded check in `FireBlast.validate` inherited by Lava. Fire Blast allows air; ordinary Lava requires stationary ground; instant proc Lava allows air; Pyre requires actual ground. Pyre becomes instant in C03, preserving its current radius/damage/cooldown until C07 hardens area selection. Stationary Lava cancellation uses real player movement/airborne state, not ambiguous tooltips. Test movement input before start, during cast, on release boundary and after release. ## Opus VFX assessment and root decisions

The [parallel assessment](opus-vfx-assessment-2026-10-10.md) was produced by the existing Claude Opus 5.5 session. Orca showed high effort and a completed turn; the worker itself could not independently confirm its effective effort setting. It performed source/API inspection only. Accepted: reuse the existing billboard/material/socket/audio path; allocate independent effect instances; use role-specific streak/sphere/ring/smoulder/halo/orbit shapes; pool floating numbers; add reduced motion; give VFX no authority over hits. Persistent burns and buffs should be subdued, with bright accents reserved for impacts/proc availability. Keep enemy feet and telegraphs visible.

Corrections and limits:

- The current queue is **not a 20 ms window**. The condition `castElapsed + 0.02 >= castReleaseTime` accepts during a later part of the animation, subject to the earlier GCD rejection, and excludes Lava. The principal defect is animation-bound and inconsistent availability.
- The proposed 100–150 ms delay on an instant is rejected. The accepting update releases gameplay and starts visible feedback; a short cosmetic follow-through may continue. Target selection changing alone will no longer cancel an accepted hard cast.
- A global event bus and an elaborate emitter framework are unnecessary. Use a narrow owner/drain interface and the existing reusable systems. Simultaneous effects require independent slots, not necessarily a replacement of every VFX file at once.
- The suggested 1,024 sprite slots would roughly double existing capacity without measurement. Begin with measured existing occupancy and enforce a bounded budget. Counting sprite-allocation calls proves only that allocation category, not zero heap allocation or zero GPU growth.
- Hostile mechanics that can affect the player have highest visibility priority, followed by own action/target feedback, then ally decoration. Never drop an important enemy telegraph solely because it is 40 m away or a cosmetic pool is full. Reserve capacity for mandatory cues and reduce decorative emission first.
- A maximum of two transient combat lights is a trial ceiling, not an instruction to add two lights. Prefer the existing shared lighting path, no additional shadow maps, and no per-target material clones. Verify shared uniforms do not overwrite another active spell's illumination.
- Installed 1.31.1 really exports a Node Particle path (`parseNodeParticleSetFromSnippet`, `buildNodeParticleSet`, `createParticleBillboard`), despite the high-level comparison table's Classic particle gap. Root confirmed API presence, not its runtime suitability. Keep it out of the critical path; no engine upgrade or particle-system replacement is required.
- Native `createAudioBusAsync`, `enableSpatial`, billboard APIs, masks/weights/fades and crossfades are present. Spatial sound, flipbooks, dynamic ribbons and NPE remain optional until a tiny installed-version proof is useful. Source clips need provenance and actual rig review; a mere speed increase is not accepted visual quality.
- Reduced-motion config tests are necessary but insufficient: review actual live reduced-motion footage. Audio and UI must remain usable when effects are reduced or sound is unavailable.

C10 can be delegated as three bounded passes after C02: (1) port simultaneous direct/projectile effects with caps, (2) burn/proc/ward/telegraph grammar and floating numbers, (3) role-specific audio and reduced-motion polish. Each pass has a before/after live clip, unchanged damage trace, disposal check and isolated performance result. New source-rig animation and shared HUD wiring remain root-owned.

## Acceptance and performance budget

- **Responsiveness:** acknowledge accepted/queued input within one presented frame at healthy pacing; instant gameplay release in the accepting update; queued start on first eligible update. Measure browser input receipt→simulation and receipt→render separately. Do not call them physical input-to-photon or network latency. Capture 100-action traces plus ordinary live play.
- **Fair rules:** no hits through solid walls/separate floors, no duplicate damage/kill/XP, no animation-dependent cooldown, no hidden stale actions, no paused-tab catch-up damage. All intended modal/input/lifetime paths tested.
- **Combat performance:** isolated M1 Max, uncapped Chromium WebGPU, actual 1280×720/DPR1, known seven-enemy region, three 12 s windows per representative combat route. Target median ≥144 FPS, every run >120 FPS, p99 ≤10 ms and matched-baseline median regression ≤5%/p99 increase ≤1 ms. Report p50/p95/p99/worst and counts >16.67/33.33/50 ms. If target and non-regression disagree, investigate before accepting; never lower resolution to pass.
- **First-use versus steady state:** separately record first cast of each ability, first proc, first simultaneous area hit and first enemy cast. Keep startup/streaming stalls visible in results; a settled FPS average does not erase them. Measure exact emitted compressed bytes/requests and first-play delta against the pre-overhaul build. Existing one-second startup failure remains a separate issue; no new VFX work in the blocking load path.
- **VFX budgets, provisional until C01/C10 measurement:** no additional shadow maps; no permanent spell lights; pooled reusable effects and a fixed voice cap. Local player/target and hostile telegraphs get priority; distant ally decoration can drop. Test 1/8/32 concurrent spell effects independently of character-count tests. Do not imply this proves hundreds of networked players. Record draw calls, triangle count, transparent coverage proxy, pool highs and retained CPU/GPU resources where observable.
- **Readability/accessibility:** shapes and motion distinguish direct hit, periodic damage, proc, friendly zone and hostile telegraph; color alone is insufficient. Reduced flash/shake toggles, scaleable HUD and optional cue audio. Keep target and feet visible. Essential cooldown/proc cues remain visible when decorative effects are reduced.
- **Balance/encounter:** 90 s sustained play does not collapse into no-mana waiting; zero-mana filler remains useful; proc cannot recursively generate itself; resource/spender choices remain meaningful. Mortal encounter includes avoidable damage, a useful interrupt, a movement opportunity and a safe return. Record time-to-kill, damage taken, unused/wasted procs, burn uptime and avoidable-hit counts; do not tune solely to damage-per-second.
- **Lifetime:** repeated fights and 20 min bounded soak; death/respawn/scene unload/asset failure/equipment changes; stable pool/listener/resource counts and clean disposal. Never claim GPU memory measurement from JavaScript heap alone.
- **Delivery:** review actual motion at normal speed, verify VE MP4 bytes/MIME/range/play/seek and Telegram dimensions. Production uses exact sealed candidate, actual custom-domain integrity and default-entry/mortal combat checks; record prior canonical and rollback failures. No success claim from an upload acknowledgement alone.

## Risks and decisions to revisit through play

The largest risk is adding mechanics before fixing action timing. Ship C03 as an observable improvement early. The second is overloading a solo player with seven buttons; introduce 1–4 first, then the utilities through enemy lessons. A proc should create an opportunity, not punish every missed 300 ms cue. The third is preserving large cinematic anticipation on nominal instants; shorten/re-author the gesture rather than hiding delayed gameplay.

The proposed free moving filler may make stationary Lava unattractive; C11 compares movement opportunity cost and damage. Conversely, excessively efficient Lava may make Fire Blast pointless. The 15% crit/three-Ember rule, Brand damage/refresh, resource rate, range, target cap and burst duration all need measured iteration. Keep these in one table, record changes, and avoid adding more mechanics to repair basic tuning.

Multi-charge abilities, channelled spells, ground reticles, dispels, full crowd-control diminishing returns, PvP balance, healing/tanking classes, talent builds and extensive gear stats follow only after this kit and encounter feel good. The first shipped system should leave room for those features without implementing their complexity now.
