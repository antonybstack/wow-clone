## 1. Timing / queue / resource / proc / projectile / periodic contracts

The scheduler, one-slot queue, reservation, Ember snapshot-at-press, independent flights, and Brand pandemic formula are implementable as written. Four contract holes will produce opposite “passing” implementations.

### 1.1 Queue lateness, 120 ms hitch, and the 50 ms render clamp disagree

**Defect.** Plan Timing: “Deadline is readiness plus one simulation update, capped at 100 ms lateness; do not resurrect an old queued action after a hitch or pause.” Same section: test 120 ms active stalls; gaps over 500 ms enter visible solo pause. C02 tests list 30/60/144 Hz and a 120 ms hitch with exact spend/hit counts.

Current clock (`src/ashen-reach/main.js` `onBeforeRender`): `const dt=Math.min(.05,ms/1000)` shared by Havok kinematic step, `combat.beforeAnimation`, `body.update`, and `combat.afterAnimation`. A 120 ms stall today becomes one 50 ms step and lost time.

Three legal readings of the plan:

- One 120 ms combat step: queued action is 120 ms late, exceeds the 100 ms cap, is dropped.
- Substep at ≤50 ms: the action starts on the first substep after readiness and the hitch test must keep it.
- Combat uses unclamped dt while body/Havok stay clamped: GCD/ticks/projectiles advance 120 ms, contact and animation advance 50 ms.

C02 “readiness-to-start at most one update under normal pacing” does not pick among these. Fix in the Timing section before C02 tests: name the combat step (shared clamp, combat-only substeps, or full dt up to the 500 ms pause), and write the 120 ms hitch expected result for the queue (execute vs clear). Do not unclamp Havok to make the test pass.

### 1.2 C02 “current values” omit Fire Blast’s 0.55 s release

**Defect.** C02: centralize cast/GCD/cooldown/resource metadata with current values; gameplay deadlines authoritative; presentation consumes events once. C03: Fire Blast releases at successful acceptance.

Authored timings today:

| Ability | Spell config | Motion `releaseTime` |
|---|---|---|
| Fire Blast | `FIRE_BLAST` has **no** `castTime`; 1 s personal CD | `ashen-playable-motion.js` `castMotion.releaseTime: .55`, `followThrough: .85` |
| Lava Ball | `castTime: 1.5`, `cooldown: 3` | `1.5` |
| Pyre Burst | `castTime: 1.1`, `cooldown: 6` | `1.1` |

Release is still `afterAnimation` waiting on `body.getState().castElapsed >= castReleaseTime` (`combat.js`). If C02 copies only `src/spells/*`, Fire Blast is already a 0 s gameplay cast while `castingShoot` still holds 0.55+0.85 s and the old `queuedCast` path still waits on `!body.getState().castingShoot`.

C02 ability table must include an explicit Fire Blast `castTime: 0.55` taken from the motion profile, with the scheduler ignoring `castElapsed` for deadlines. C03 then sets that field to 0. Leave this implicit and C02 either ships accidental instants with an animation lock, or a clock that still follows the pose.

### 1.3 Same-time tick vs player release is unordered

**Defect.** Timing order: “interrupt/death before same-time release; release before generated impact; tick before same-time aura expiry.” Fair rules and C05 require no duplicate kill/XP.

Tick vs player release at the same timestamp is not placed. Brand tick and Fire Blast release at t=T can both observe a living target, both apply lethal damage, and both try to award XP. `updateEnemies` currently awards XP on `hp <= 0` the following `beforeAnimation`; two writers in one `afterAnimation` already mutate `target.hp` directly (`FireBlast.hit`, `GravePulse.hit`, `connectSwing`).

Add one line: at equal time, ticks before player releases before melee contact, and all damage goes through one apply that awards kill/XP once. That is a rule, not a framework.

### 1.4 Lava’s existing 3 s personal cooldown vs C06 Surge spender

**Defect in milestone mapping, not in the kit table.** Kit: Lava Ball “no personal cooldown.” `LAVA_BALL.cooldown` is 3, started in `LavaBall.release`. GCD is 1.5 s, so Lava cannot be recast every GCD today. Ember Surge “makes the next one instant/free.” Tuning is “introduced explicitly from C03/C05 onward”; C06 names proc/queue races and two airborne flights, not CD removal.

If C06 ships on the current 3 s CD, a banked Surge can sit on an unusable Lava. Pin “Lava personal cooldown = 0” on C05 or C06 in the kit/milestone table. The 3 s value itself is current baseline, not a feel target.

### 1.5 Documented and implementable (not defects)

- Queue 300 ms, last press wins, no spend at queue, revalidate at execution, generation lock: consistent with `queuedCast` being animation-bound and Lava-excluded today (`combat.js` `beginSpell` / `gcd > 0.04`).
- Instant commit on acceptance vs hard-cast reserve/commit/refund: matches current GCD-at-start and mana-at-release once reservation is real. `spendMana` return value is ignored on Lava release today; C09 off-GCD Ward during Lava makes that racy unless C02 reservation is generic.
- Ember: store variant at press; expired proc does not convert to a hard cast. Inverse (queued hard-cast Lava while Surge banks later) stays a hard cast. That is an intentional snapshot, not a contradiction.
- Brand `expiry = now + base + min(remaining, 0.3 * base)` with preserved `nextTickAt` and no fractional last tick: implementable. “Refresh near expiry” is advice for the player, not a second rule.
- Eight flight slots vs 4 s / 60 m / ~1.3 s GCD: capacity is ample. Gameplay slot exhaustion vs cosmetic pool is already split correctly.
- Homing from C06 with wall stop and no retarget: a deliberate gameplay change, already labelled.

## 2. Milestone dependencies and ownership

Sequence C01 evidence → C02 scheduler → C03 contact/instants → C04 HUD → C05 auras/mana → C06 proc/flights → C07 area → C08 enemy telegraphs → C09 off-GCD → C10 VFX integration → C11 encounter is workable. No Babylon upgrade, Classic particles, global bus, or extra `requestAnimationFrame` is required. Installed Lite 1.31.1 animation masks/weights/crossfades are enough for C03’s 80–120 ms recovery preempt.

Fix three dependency holes. Do not add engine work to paper over them.

### 2.1 C02 must drain multiple intents; `spellPressed` cannot

**Defect.** C02 `requestAction(intent, now)` plus C09 “atomic simultaneous actions” and off-GCD during an offensive GCD. Current input is one scalar: `input.spellPressed` overwritten on every keydown, consumed once in `beforeAnimation` (`src/input.js` `SPELL_KEYS`, `combat.js` ~678–696). Digit 4–5 are already mapped; Digit 6–7 are not. HUD clicks also write that scalar.

If C02 keeps polling one slot, Quench/Ward during a queued Lava, or two keys in one frame, drop an intent. Call `requestAction` from keydown/HUD (sequence preserved) or drain a per-frame list. That is the existing `notifyActionInput` boundary, not a new input framework.

### 2.2 Event-contract freeze at C02 is safe only if durations are data

C10 “can prototype after C02 contract”; ownership freezes `*-vfx.js` after C02. That holds if start/release/impact events already exist in C02 and Fire Blast’s 0.55 s is a data field (see 1.2). If VFX binds to `castElapsed` or `beginWindup` timing, C03’s instant Fire Blast and C07’s instant Pyre rewrite the freeze. Keep root ownership of `combat.js` / HUD wiring as the plan says; do not freeze animation-timed cues.

C07 acceptance “without covering enemy telegraphs” names C08 content. Move that clause to C08/C10.

### 2.3 C03 movement interrupt applies to Pyre until C07

**Feel sequencing, high impact.** C03: stationary casts interrupt on translation/jump; no blanket `CAST_MOVE_SCALE = 0.4`. Pyre remains a 1.1 s cast until C07 (“Instant grounded release”). Today Pyre walks at 0.4 during charge (`beginSpell` sets move scale for every key). C03 then cancels Pyre if the player strafes; C07 later makes it instant.

Either treat Pyre as instant in C03 (grounded check only), or exempt it from the C03 movement interrupt until C07. Shipping a worse Pyre for three milestones is not “first feel win with the existing three spells.”

Root vs Opus vs Grok ownership in the Engineering section is otherwise sound. C11 depending on C10 is acceptable if the core loop is playable at C09; do not block C05–C09 on VFX.

## 3. Missing gameplay-feel, correctness, or acceptance

### 3.1 Escape vs pointer lock (correctness of the stop-cast rule)

**Defect.** Plan: “Escape first stops the current cast and queue, then follows existing target/menu behavior on a subsequent press.”

`src/input.js` keydown: if pointer-locked, Escape exits lock and **returns without** `input.escape`. A 200 ms guard then swallows the next Escape. Combat’s Escape handler only `targeting.clear()` (`combat.js` ~636–638). Menu open also swallows Escape.

Under RMB mouselook, the first Escape never reaches the scheduler. Stop-cast becomes unlock → wait → stop, or unlock → clear target, depending on timing. C02 Escape tests must include pointer-lock and menu, and the Timing bullet must say which press stops a cast while locked.

### 3.2 Kindle with no target

**Gap.** Kit: “Instant, GCD, 45 s cooldown, 10 s duration, 15% haste” and “Immediate 30-damage ignition on a valid target plus buff.” If the whole ability requires a hostile, Kindle cannot open a burst while moving with no target. Specify: self-buff always on acceptance; ignition is a bonus that needs a valid target, or the press fails without the buff. That is a rule, not a number change.

### 3.3 Caster death, dummy recover, and aura identity

**Gap.** Periodic: aura key `(source ID, target generation, effect ID)`; “Death, despawn, leash reset and disposal remove relevant auras”; launched effects must not attach to a reused ID.

Enemies keep the same `id` across `respawn` (`enemies.js` `respawnDelay: 8`). Dummy recover is the same object (`recover: true`, 3 s HP reset in spell classes). Plan does not say:

- caster death / Release spirit clears outgoing Brand/Kindle/Ward;
- dummy HP reset increments generation (it should not, if it is the same actor);
- enemy `respawn` increments generation (it must, C06 reused-ID test).

8 s respawn vs 4 s projectile lifetime hides this until C11 shortens respawn. Put generation increment on enemy respawn in C02, and caster-death aura wipe in C05.

### 3.4 Instant facing snap while steering

**Gap.** Timing: retain forgiving idle auto-face; “while steering, don't snap the camera or override movement.” `beginSpell` still `player.setFacing` toward the target for every non-Pyre spell (`combat.js` ~379–383). C03 running/jumping Fire Blast will yaw the body on every press. C01 facing-cone recording is not enough; C03 acceptance needs: idle auto-face only when not translating/turning/RMB, and `setFacing` must not cancel a jump or Havok velocity.

### 3.5 Shared `FireBlast.validate` grounded rule

**Gap.** `LavaBall extends FireBlast`; `validate` rejects `!grounded` for both (`fire-blast.js`). Plan: instants work airborne; Lava interrupts on jump/translation; Pyre grounded at **execution**. C03 “rules explicit per ability” must actually split validators. Leaving inheritance in place makes airborne Fire Blast impossible without also allowing airborne Lava.

### 3.6 Auto-attack “casting” still equals pose

**Gap.** Plan C03: melee pauses through hard casts, not cosmetic recovery. `tickAuto` sets `casting = !!pending || !!body.getState().castingShoot` (`combat.js` ~499). `stepAutoAttack` freezes the swing timer while `casting` (`auto-attack.js`). After C03, Fire Blast recovery still sets `castingShoot` for follow-through, so auto-attack keeps pausing through the pose the scheduler no longer owns. Drive `casting` from scheduler hard-cast state only.

### 3.7 Off-GCD during a hard-cast has no body owner

**Acceptance gap, not a blocker.** C09: Quench/Ward execute during an offensive cast; “VFX cannot steal the cast animation owner.” There is no spare upper-body slot (`body.js` one `castingShoot` / `activeCastProfile`). C09/C10 should accept HUD/VFX-only acknowledgement while Lava occupies the rig, and test that Ward/Quench do not call `cancelCast` or replace `input.castSpell`.
