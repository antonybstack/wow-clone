# Babylon Lite documentation and Ashen Reach audit — 2026-09-25

## Scope and method

The active target is the root Ashen Reach game (`ashen-reach.html`, `src/ashen-reach/`, `src/player.js`, camera, character runtime) and its supporting scripts. Archived Duskwell code is historical and is excluded from refactoring recommendations. This is a **documentation and code audit**, not a library upgrade or a claim that every candidate has been performance tested.

I inventoried and read all **71 authored Markdown pages** under the official Babylon Lite [`docs/lite/` tree at commit `2e064d88`](https://github.com/BabylonJS/Babylon-Lite/tree/2e064d88ec7422af946f8ec7f089ac6519f99295/docs/lite), including all 64 architecture pages, six introductory guides and the bundle-size follow-up. The page-by-page disposition is below. I also fetched and parsed all **1,817 generated [Lite API reference](https://doc.babylonjs.com/lite/typedoc/) symbol pages**, indexed their descriptions and scanned their content for deprecation/experimental notices on imported APIs. I checked the 147 distinct Lite symbols statically imported by active source and scripts and read reference entries relevant to each finding. **142 imported names appear as direct API index pages**; none of those pages carried a deprecation or experimental notice. The other five are the older `mat4*` aliases listed in the version finding and `AnimationGroupMaskMode`. This is a systematic API-page scan, not a manual semantic review of all 1,817 unreferenced types. All 1,817 pages responded successfully during this audit.

The game installs **`@babylonjs/lite` 1.28.0** and Havok 1.3.14. npm's current Lite release on this date is **1.31.1**. The pinned authored docs and generated API reference describe a newer surface. Each finding below says whether the needed API exists in 1.28.0. Classic `@babylonjs/core` examples are not treated as Lite instructions.

| Representative API | Installed 1.28.0 | 1.31.1 | Audit relevance |
| --- | --- | --- | --- |

## Checks that avoided false refactors

- Loading a whole glTF container and then adding its animation groups to a separate manager **does not double tick**: Lite's scene tick skips groups with `_animationManager`. The active character pattern is already supported.
- Tiled woodland LOD operates on batched tree meshes, whereas Lite's thin-instance LOD partner works on thin instances. It is not a direct substitute for the current 128 m tile/hysteresis design.
- Native contact-shadow and effect tasks, sprite billboards, Havok ray/shape queries, glTF, HDR, texture loading, audio, parenting and thin-instance updates are already used where they fit. The authored WGSL environment, continuous traversal routes and MMORPG controls carry game-specific behavior.
- The [null engine](https://github.com/BabylonJS/Babylon-Lite/blob/2e064d88ec7422af946f8ec7f089ac6519f99295/docs/lite/05-headless-null-engine.md) could make primitive fixed-step physics tests cheaper, but its documented mesh/convex-hull collider limit means it cannot replace the current live terrain and cathedral traversal checks.
